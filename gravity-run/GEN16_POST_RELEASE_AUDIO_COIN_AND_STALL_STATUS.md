## Opt-in, bounded audio diagnostics

`SfxController` records only while a diagnostic capture is explicitly active. The fixed limits are 128 SFX requests, 64 callback intervals of at least 50 ms, and 48 coin contacts. SFX records include monotonic request time, event type/key, accepted or rejected status/reason, voice/playback type and Godot mix timing. Start/end snapshots include AudioServer mix rate and effective output latency, SFX/music playback type and music playing state. Callback intervals contain process/physics callback, elapsed interval, engine delta and simulation tick. Coin samples contain swept contact fraction, player start/end pose and the claim submission/rejection state. No profile/user account token, nonce or credential is recorded.

The MP diagnostics menu now has a separate “Capture audio timing (12 s)” control. It auto-stops and its result is included in the existing **Save diagnostics** JSON export. The actual match-overlay integration test shortens the duration to 50 ms, sends touch/release through the viewport at the visible control rect, verifies no gravity flip is queued, then exercises the control's pressed handler and confirms it closes the overlay, auto-stops, and exports JSON with bounded SFX events and no screenshot readback/image-series fields. The headless test reports whether Godot dispatched synthetic ScreenTouch to the Button (`MP_AUDIO_TOUCH_DISPATCHED`); if not, it calls the pressed handler directly so the capture lifecycle still gets tested. This does not claim a real-device Button hit test. The existing right-edge screenshot capture remains a separate opt-in tool.

On SP, `?singleplayer_capture=audio` is handled by the separate lightweight `systems/sfx_audio_diagnostic_capture.gd` node. `main.gd` only creates it after the normal run has started, passing the active run seed and generator version; it does not route through the older frame-pacing/render-capture fixture. The node records bounded SFX/callback/coin data, auto-stops after 12 seconds, and offers a JSON download through the existing diagnostics exporter. The actual-main-scene regression starts the node with the active run seed/version, lets it finish, invokes the download method and parses the resulting JSON; it verifies that challenge state/ruleset/seed/version remain unchanged and that no screenshots or render-detail frames are included. Web reports include bounded `navigator.userAgent` and `navigator.platform` values (192/80 characters maximum) alongside visibility/focus and viewport; no account or credential data is included. The Web query/auto-download itself was not exercised in a browser during this pass.

The MP start handler closes the diagnostics overlay, cancels an in-progress touch gesture and clears queued gravity-flip input. The integration test sends a touch/release over the audio control, verifies no flip is queued, invokes the same button signal handler used by the UI, then confirms tracing continues after the overlay closes and that **Save diagnostics** exports the trace without image-series data. In the headless scene runner, synthetic touch events do not reliably dispatch through Godot's Control GUI layer, so the button signal is invoked directly after the touch lifecycle check; this is not claimed as a real-device GUI touch test. The screenshot burst remains covered separately by `right_edge_capture_contract_test.tscn`.

AudioContext state/output timestamp is not currently available through Godot 4.7.2's GDScript Web driver API. The generated Web audio driver keeps the JS context private (`GodotAudio.ctx`) and Godot exposes its effective output latency through AudioServer, not the raw `AudioContext.outputTimestamp`. The diagnostics therefore report context/output timestamp unavailable unless an external probe is explicitly installed; no such probe is bundled. AudioServer latency is sampled only at capture boundaries. No playback-type or asset change was made: Web is exported without thread support, music uses Stream, and a prior Sample attempt reported a WebAudio buffer error. Actual mobile Chrome audible timing still requires a trace from the affected device/browser.

## Still unresolved

The current capture measures app request time and Godot's mix/latency values, not physical/browser output time. The optional externally installed `window.__gravityRunAudioContextProbe` hook is not bundled or verified.

The prior Gen15/Gen16 45k planner probe used seeds 100000014 and 100000918 and showed more synchronous work in three of four aggregate samples, with an individual 8.1 ms `ensure_horizon` phase on the test host. It is not a browser-frame capture and does not establish the user's stall cause. The standard grounded SP coin contact passed its earlier actual-scene probe; this task's added trace should capture hitbox/tick/ledger details if the user can reproduce a missed pickup.
