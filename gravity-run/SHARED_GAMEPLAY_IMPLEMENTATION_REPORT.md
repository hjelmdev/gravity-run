# Shared gameplay implementation report

## Delivered

- Generator version 5 adds common course coins, versioned density tuning, and falling rocks. The v3/v4 course-generation contract remains unchanged; the root review compared seeds 1, 42, and 918273645 against six frozen HEAD fixtures and confirmed exact event, fingerprint, course identity, and full-hash matches.
- Coins are manifest entities shared by all runners. The first validated swept contact wins, the host commits the pickup through the reliable world ledger, and the coin disappears for all peers. Account awards use a frozen round catalog and roster/account binding, a host journal, authenticated incremental settlement, and retryable idempotency. Settlement responses include cumulative earned counts scoped to round, room generation, network identity, and account. The result UI remains pending until that exact recipient's confirmed count covers the local awards; no-op and unrelated-round settlements cannot mark it saved. SP coins are swept against the same fixed-step motion and are collected before `finish_run` when their contact precedes the terminal hazard.
- V5 course density is 1.5. The shared generator preserves the normal spawn/forecast lead for existing moving hazards; rock-only early preparation does not shift their layout or forecast.
- Falling rocks have a warning, a 20-tick fall, and a persistent partially buried lethal hitbox. Rock state is kept in the world ledger/baseline and its render pose preserves fractional presentation time. A late guest activation commit is logged and tested against the runner's actual current state, cooldown, world surfaces, maximum speed, a 200 ms reaction margin, and swept rock path. A route that remains physically safe may continue; otherwise the guest pauses for existing reconnect/baseline synchronization and is eliminated under a connection-fairness reason after sync, without applying a retroactive rock collision.
- Added a private review scene at `tools/shared_gameplay_visual_fixture.tscn` showing dormant, warning, falling, and buried rocks with coins. It is not linked from the public menu.

## Verification

- Godot 4.7.2 headless editor load completed without project parse errors. Godot printed a Windows root-certificate-store warning in this environment.
- Passed `course_generator_test.gd`, `course_manifest_test.gd`, `race_course_presentation_test.gd`, Multiplayer V2 contract tests, session lifecycle tests, and the real native WebRTC session suite.
- The world ledger keeps its full internal dictionary for simulation and hashing, but baselines use a versioned compact positional-row codec that retains entity ID, incarnation, state, revision, health, coin winner/value, and rock activation. Decode validates every row and replaces the state atomically; malformed versions, types, duplicate/missing/unknown IDs, incarnation mismatch, and impossible revisions are covered by regression tests. Host preparation measures the complete `WORLD_BASELINE` control envelope before catalog registration or `COMMIT_START` and rejects a course over the selected 48 KiB application budget. A 200-seed default-course sweep measured a maximum of 27,308 bytes (seed 43). The real native WebRTC session passed this final codec at that exact seed/size and resynced the claimed coin on both clients. Root also passed Chromium WebRTC with the exact compact baseline (27,308-byte control, seed 43, 214 coins): three JS clients connected, both guests restored the claimed coin, and three result/ACK/lobby cycles preserved peer IDs with no console errors. This was a loopback of three logical clients in one Chromium instance, not a live authenticated account match. The 48 KiB value is an application guard with substantial headroom under the observed JS receive buffer, not a negotiated transport guarantee.
- The v5 seed-profile test built 128 distinct 45,000 px seeds and found 88 accepted rock events across 63 seeds. Accepted events carry the 1,100 px trigger lead, 36 warning ticks, and 20 fall ticks.
- Root's independent tests passed for: coin pickup-before-death ordering (including exact-tick and after-death rejection, with `finish_run` once); contact-time coin arbitration and retry; the settlement retry timer; rock phase boundaries and exact first dangerous tick; buried hitbox/render alignment; and rock safe/unsafe route cases at 250/500/750 px/s with initial cooldown 0/0.84 s. Root also verified two same-profile rocks at different course positions spawn once each in a real SP scene.
- Root's late-delivery route probe passed: a 200 ms and 300 ms delayed activation with a remaining safe route continues; a runner already at x=1,960 when the rock is buried is treated as unsafe. The durable account-context regression covers account changes during binding, no-op-before-journal, partial cumulative settlement, other-round/other-network rejection, duplicate/lost-reply monotonicity, and room A/generation 1 to room B/generation 1 scoping. The warning visibility fixture confirms the offscreen indicator is available from delivery; at 750 px/s the rock enters the 960 px camera at activation+20 ticks, leaving 16 ticks (267 ms) of in-camera warning before the fall. A RunnerMotion case with 0.84 s residual cooldown and a 200 ms response margin flips safely using the earlier offscreen marker.
- Root's local PostgreSQL tests verified a fresh 36-migration chain, authenticated RPC authorization, roster/account binding, nonce/replay rejection, duplicate/retry behavior, per-round cumulative settlement confirmations, room deletion, concurrent journal/settlement behavior, and wallet credit exactly once. The latest settlement payload is bounded to the most recent 32 rounds for the signed-in account while wallet settlement still processes all pending awards. SQL execution used a loopback PostgreSQL instance with Supabase auth/realtime shims; it did not exercise live GoTrue/PostgREST or a production backend.
- Final density measurement (root's independent HEAD comparison, 200 seeds × 45,000 px): lethal-event footprint count mean 65.835 → 68.43 (+3.94%); lethal-only hazard-free distance median 485.2726 → 391.0155 px (-19.42%), p90 1,270.4100 → 1,209.3643 px (-4.80%), max 4,514.5398 → 5,728.4116 px (+26.9%). 142 rocks were accepted across 100/200 seeds. The 15–20% reduction target is reached at the median; p90 improves less and the worst quiet gap grows, so the tail objective is not met. The outlier has not been isolated to a single cause. Slope is intentionally excluded from this lethal-hazard union. These are geometric spacing proxies, not measured player reaction-time outcomes.

## Limits and rollout

- Root's final review passed the compact baseline and account-context regression tests again, and loaded an isolated project with feature-only `main.gd` successfully. The earlier, unrelated singleplayer capture edits were excluded from that copy and preserved in the original working tree.

- The account-award migration has only been exercised on the isolated local PostgreSQL test instance. No live migration, deployment, publication, or push was performed.
- The larger maximum-length manifest has not been demonstrated against transport limits. The 48 KiB value is an application guard selected from the measured default-course distribution, not a claim about an SCTP transport guarantee.
- The visual fixture was independently reviewed in a browser: dormant, warning, falling, and buried phases and coins were visible without clipping. This validates fixture rendering, not a live authenticated match.
- Longer-tail density tuning remains open: p90 improves only 4.8% and the worst quiet interval grew 26.9%, despite the median reaching the target. Increasing density blindly was rejected because the route solver and rock switch clearance are hard fairness constraints; this tail tradeoff is reported rather than presented as solved.
- Rollout build ID is `2026.10.02-shared-gameplay`; the Multiplayer V2 compatibility version remains `2.1.20261001.1`, matching the coin-award migration's explicit gate. The linked project had all prior migrations through `202609300002`; a dry run listed only `202610010001_shared_coin_awards.sql`, which was applied and then verified in linked history as local=remote. This verifies migration history/application, not a live GoTrue/PostgREST account flow. The source change is being committed/pushed separately from Pages; the matching migration is now in place before frontend publication.
- Existing singleplayer capture/pacing edits, music changes already present on the branch, and unrelated untracked plans/files were preserved outside this feature commit.
